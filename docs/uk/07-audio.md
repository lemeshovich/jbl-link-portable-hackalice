## Як влаштований ALSA на колонці

Найважливіше з `/etc/asound.conf` на цій прошивці:

```
default ──► shadow_softvol (control "ShadowMaster") ──► ... ──► dmixer ──► hw:0,0
softvol ──► softvol (control "Master") ────────────────────────► dmixer
hmpp    ──► Harman DSP plugin (type hmpp) ──► ch2route ─────────► dmixer
```

- **Аліса** говорить через `default`, тож її гучністю керує `ShadowMaster`
  (numid 120).
- **Кнопки гучності** рухають одночасно `Master` (numid 128) і `ShadowMaster`, від
  0 до 999.
- **Bluetooth** іде через `hmpp` — обробку звуку Harman. Саме вона дає колонці
  налаштовані баси; все, що її оминає, звучить помітно пласкіше.
- `dmixer` — це `dmix` зі спільною пам'яттю на ключах 1024 і 1025.

## Наш вихід ytmout

Для ytm-play ми зробили власний пристрій `ytmout`: softvol на регуляторі `Master`,
який віддає звук у `plug:hmpp`. Тож ним керують кнопки, і звучить він через ту
саму обробку Harman, що й Bluetooth.

Домашній каталог `/home/root` лежить на кореневій системі, а вона лише для
читання, тож `~/.asoundrc` не підходить. Натомість програвач отримує змінну
`ALSA_CONFIG_PATH`, яка вказує на [device/ytm/my.conf](../../device/ytm/my.conf). У
цьому файлі треба підключити **обидва** конфіги — основний ALSA і системний — і
лише потім описувати `ytmout`:

```
</usr/share/alsa/alsa.conf>
</etc/asound.conf>
pcm.ytmout { type softvol  slave.pcm "plug:hmpp"  control { name "Master" card 0 } ... }
```

Без першого рядка ALSA навіть не знає, що таке `plug`.

Є й приємний бонус: Аліса сидить на `ShadowMaster`, а музика — на `Master`, тож
ytm-alice може на мить заглушити тільки Алісу, а музика гратиме далі. Про це — у
[розділі 10](10-voice-control.md).

## Завислі підключення до dmix

Якщо програвач, що грає через `dmixer`, вбити жорстко, його підключення до
спільної пам'яті може лишитися висіти. Назбирається кілька таких — і замовкне
Bluetooth. У BusyBox немає `ipcrm`, тому ми написали
[tools/ipcclean.c](../../tools/ipcclean.c). Лікується так:

```
/data/ytm/bin/ipcclean dmix
systemctl restart linkplay.service      # пролунає сигнал JBL
```

ytm-play звільняє своє місце в обробнику `atexit` і закриває сокет в обробнику
сигналів, тож із ним таке вже не повинно траплятися.

## Що прошивка не вміє декодувати

YouTube Music віддає AAC у контейнері MP4, звичайному або фрагментованому. А на
цій прошивці:

- у GStreamer немає ні декодера AAC, ні розбору MP4; MP3 грає через libmad;
- у `libquasar_gstreamer.so` потрібні елементи є, але назовні вони не
  експортуються;
- `/system/workdir/lib/libfaad_drm.so` має API faad2, але зібраний для Digital
  Radio Mondiale і на звичайний AAC відповідає помилками 29 і 30.

Тож довелося написати власний програвач із власним faad2 — [розділ 08](08-ytm-play.md).

## Підступне підсилення після завантаження

`HW Gain1 Volume` (numid 7) — це апаратне підсилення кодека. У нормі воно
`524288`.

На щойно завантаженій колонці звичайне читання регулятора

```
amixer -c0 sget Master
```

скидає його до `64`. Колонка практично замовкає, Аліса теж, і так триває, доки
не перезапустити `linkplay.service`. Після такого перезапуску та сама команда вже
нічого не ламає — тому ця проблема так довго й ховалася: кожна ручна перевірка
відбувалася одразу після перезапуску, яким ми й рятували звук.

Повернути `HW Gain1 Volume` через `amixer cset` теж не вийде — він одразу знову
стає `64`. Правильне значення виставляє лише старт Linkplay.

А от звернення безпосередньо до **елемента** регулятора нічого не ламає:

```
amixer -c0 cget numid=128        # або name=Master
amixer -c0 cset numid=128 500,500
```

ytm-alice використовував `sget`/`sset Master`, щоб показувати й змінювати
гучність під час трансляції. Наш патч замінив їх на звернення до елемента.

## Як таке шукати

Порівняйте стан мікшера до і після:

```
amixer -c 0 contents > mix-bad.txt
# повертаємо звук, а потім
amixer -c 0 contents > mix-good.txt
diff mix-bad.txt mix-good.txt
```

Із 645 рядків відрізнялися п'ять, і серед них — оте саме підсилення.
