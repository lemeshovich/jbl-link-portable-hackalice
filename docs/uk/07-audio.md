## Схема ALSA

Важливі частини `/etc/asound.conf` на цій прошивці:

```
default ──► shadow_softvol (control "ShadowMaster") ──► ... ──► dmixer ──► hw:0,0
softvol ──► softvol (control "Master") ────────────────────────► dmixer
hmpp    ──► Harman DSP plugin (type hmpp) ──► ch2route ─────────► dmixer
```

- **Аліса** говорить через `default`, тож її гучність — `ShadowMaster` (numid 120).
- **Кнопки гучності** рухають `Master` (numid 128) і `ShadowMaster` разом,
  діапазон від 0 до 999.
- **Bluetooth** іде через `hmpp`, DSP Harman. Саме він дає колонці налаштовані
  баси; усе, що його оминає, звучить помітно пласкіше.
- `dmixer` — це `dmix` із ключами спільної пам'яті 1024 і 1025.

## Наш пристрій виводу

ytm-play використовує власний пристрій `ytmout`: softvol на регуляторі `Master`,
що подає звук у `plug:hmpp`. Тож ним керують кнопки, і він отримує той самий DSP,
що й Bluetooth.

Домашній каталог `/home/root` лежить на корені лише для читання, тож `~/.asoundrc`
не варіант. Натомість плеєр отримує `ALSA_CONFIG_PATH`, що вказує на
[device/ytm/my.conf](../../device/ytm/my.conf), який має підключати **обидва** —
основний конфіг ALSA і системний — до визначення `ytmout`:

```
</usr/share/alsa/alsa.conf>
</etc/asound.conf>
pcm.ytmout { type softvol  slave.pcm "plug:hmpp"  control { name "Master" card 0 } ... }
```

Без першого підключення ALSA взагалі не знає типу `plug`.

Те, що Аліса на `ShadowMaster`, а музика на `Master`, дає ytm-alice змогу на мить
заглушити лише Алісу, поки музика грає далі; див. [10](10-voice-control.md).

## Завислі підключення dmix

Якщо плеєр, що використовує `dmixer`, жорстко вбити, його підключення до сегментів
спільної пам'яті може лишитися. Кілька таких — і Bluetooth замовкає. У BusyBox
немає `ipcrm`, тому є [tools/ipcclean.c](../../tools/ipcclean.c). Відновлення:

```
/data/ytm/bin/ipcclean dmix
systemctl restart linkplay.service      # звучить сигнал JBL
```

ytm-play звільняє свій слот в обробнику `atexit` і закриває сокет в обробнику
сигналу, тож із ним такого бути вже не повинно.

## Що прошивка не вміє декодувати

YouTube Music віддає AAC у MP4 (звичайному або фрагментованому). На цій прошивці:

- у GStreamer немає ні декодера AAC, ні демультиплексора MP4; MP3 працює через
  libmad.
- `libquasar_gstreamer.so` містить такі елементи, але не експортує жодного.
- `/system/workdir/lib/libfaad_drm.so` експортує API faad2, але зібраний для
  Digital Radio Mondiale і відкидає звичайний AAC з помилками 29 і 30.

Звідси наш власний плеєр із власним faad2: [08](08-ytm-play.md).

## Баг із підсиленням після завантаження

`HW Gain1 Volume` (numid 7) — апаратне підсилення кодека, у нормі `524288`.

На щойно завантаженій колонці читання простого елемента мікшера командою

```
amixer -c0 sget Master
```

встановлює його в `64`: колонка фактично замовкає, і Аліса теж, доки не
перезапустити `linkplay.service`. Після такого перезапуску та сама команда
нешкідлива, тому баг так довго ховався: кожна ручна перевірка робилась одразу
після перезапуску, потрібного для відновлення звуку.

`HW Gain1 Volume` не повернути й через `amixer cset`: він одразу знову читається
як `64`. Встановлює його лише старт Linkplay.

Пряме читання чи запис **елемента** регулятора цього не викликає:

```
amixer -c0 cget numid=128        # або name=Master
amixer -c0 cset numid=128 500,500
```

ytm-alice використовував `sget`/`sset Master`, щоб повідомляти й задавати гучність
для сеансу трансляції. Патч замінює їх прямим доступом до елемента.

## Як шукати таке: порівняти мікшер

```
amixer -c 0 contents > mix-bad.txt
# відновити звук, потім
amixer -c 0 contents > mix-good.txt
diff mix-bad.txt mix-good.txt
```

Із 645 рядків відрізнялись п'ять, і один із них — те саме підсилення.
