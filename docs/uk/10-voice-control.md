# Голосове керування на старій прошивці

[English](../en/10-voice-control.md) · **Українська** · [Русский](../ru/10-voice-control.md)

Що відбувається між «Алиса, включи на ютубе Daft Punk» і музикою на quasar 3.21,
і навіщо кожен крок. Усе тут з'ясовано з голосового журналу
(`/tmp/ytm-voice.log`) і `yiod.log`, а не вгадано.

## Проблема

Аліса надсилає кожну команду в хмару. ytm-alice бачить розпізнаний текст і сам
вмикає музику, але хмара теж відповіла, і Аліса от-от скаже «Воспроизведение
видео не поддерживается на этом устройстве» або «Для этого нужна подписка
Плюс…». На новіших прошивках ytm-alice скасовує це через IPC `AliceCapability`,
якого на 3.21 немає.

## Що не спрацювало

- Скасовувати щойно команду розпізнано: відповідь приходить пізніше, тож
  скасовувати ще нічого.
- Скасовувати в циклі кілька секунд: це закриває й мікрофон Аліси, тож наступна
  команда обривається.
- Замінювати відповідь порожнім запитом «повтори за мной»: йому потрібен обмін із
  хмарою на 0,3–2 с, за які встигають прозвучати перші слова.
- Повідомлення прошивки, схожі на скасування (`restart_vins_dialog`,
  `sound_cancel`, кнопка дії): на 3.21 жодного ефекту.

## Що працює

### 1. Розпізнати команду

Текст приходить у кадрі стану 1; підсумковий стан 3 — окремим кадром без тексту.
Текст переноситься (вікно 10 с). Повторена фраза вважається новою командою, якщо
між ними була подія слова активації.

### 2. Заглушити лише Алісу

У цей момент `ShadowMaster` (softvol Аліси) зберігається й ставиться в 0. Музика
на `Master` і грає далі. Збережене значення пишеться в `/tmp/ytm-shadow-saved`;
якщо демон впаде, поки Аліса заглушена, наступний запуск його відновить.

### 3. Відкинути відповідь до того, як її промовлено

Відповідь з'являється в кадрі стану 3 зі своїм текстом ще до того, як Аліса
почне говорити:

```
state 3 -> 3 speech="Воспроизведение видео не поддерживается на этом устройстве."
refusal in state 3 ...: cleanup_directive_controller
state 3 -> 0
```

Відповідь вважається відмовою, якщо в ній є «подписк», «видео», «не
поддерживается» чи «недоступ», і лише протягом 12 с після команди, яку взяв
ytm-alice, — щоб Алісу не глушили, коли її питають про інше.

`cleanup_directive_controller` — власне скасування діалогу прошивкою. Іноді
відповідь уже дійшла до звукового тракту, і Аліса ще до двох секунд «говорить» у
заглушений канал; глушіння тримається, поки вона в стані 2 з відмовою, але
загалом не довше 4 с.

### 4. Звільнити діалог

Відкинута відповідь лишає діалог в очікуванні відтворення, якого ніколи не буде:
світлодіоди крутяться («думає»), а слово активації ігнорується. Звільняє його
новий запит. Для «включи» це саме оголошення; для «пауза», «дальше» та решти —
порожній «повтори за мной», на який Аліса відповідає тишею.

### 5. Повернути голос і оголосити

`ShadowMaster` відновлюється приблизно через 400 мс після того, як відмову
відкинуто (або через 2,5 с після команди, якщо відмови не було). Лише після
цього надсилається «Включаю», бо скасування скасовує й запит у дорозі. Якщо
Аліса не відреагує на нього за 1,5 с (зазвичай реагує приблизно за 50 мс), його
буде надіслано ще раз.

### 6. Закрити мікрофон

Після будь-якого нашого запиту прошивка відкриває мікрофон приблизно на п'ять
секунд, що ще й тримає музику приглушеною. Коли Аліса переходить у стан 1 протягом
10 с після нашого запиту **без** події слова активації перед цим, демон за секунду
надсилає `cleanup_directive_controller` і повторює, поки вона ще слухає. Сесія, яку
користувач починає словом «Алиса», завжди має спершу подію слова активації, і її
ніколи не чіпають.

## Типовий журнал

```
wake word
state 0 -> 1
state 1 -> 3
ShadowMaster 610,610 -> 0 (Alice muted)
intercepted "Включи на YouTube Daft Punk" -> play
state 3 -> 3 speech="Воспроизведение видео не поддерживается на этом устройстве."
refusal in state 3 ...: cleanup_directive_controller
state 3 -> 0
ShadowMaster restored to 610,610
announce queued "Включаю" (attempt 0)
speech sent after 4ms "Включаю" err=<nil>
state 0 -> 3
state 3 -> 2 speech="Окей, повторяю за вами: «Включаю»."
state 2 -> 1
auto-listen opened after our request
auto-listen still open: cleanup_directive_controller
state 1 -> 0
```

## Якщо Аліса все ж зависла

- **Безкінечно думає** (світлодіоди крутяться, ігнорує «Алиса»): `alicesay ""`
  звільняє діалог.
- **Безкінечно слухає**: `alicesay ""`, потім `qcancel -f 170 -E`; якщо не
  допомагає, перезапустіть голосову роль:
  `kill $(ps | grep "[m]aind --yiod" | awk '{print $1}')`. Лаунчер підніме її за
  кілька секунд.
