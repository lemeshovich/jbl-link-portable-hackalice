# Перевизначення прошивки

[English](../en/05-overriding-the-firmware.md) · **Українська** · [Русский](../ru/05-overriding-the-firmware.md)

## Bind-монтування поверх кореня лише для читання

Кореневу файлову систему не можна перемонтувати на запис, але файл із `/data`
можна змонтувати поверх наявного файлу:

```
mount -o bind /data/path/replacement /system/vendor/quasar/quasar.cfg
```

Обмеження:

- лише поверх файлу чи каталогу, що вже існує; новий шлях на кшталт
  `/home/root/.asoundrc` так не створити;
- монтування зникає після перезавантаження, тож його треба повторювати з хука;
- процеси, які вже відкрили файл, бачать старий, доки їх не перезапустити.

## quasar.cfg

`/system/vendor/quasar/quasar.cfg` містить конфігурацію демонів, зокрема
`uniProxyUrl` (куди йде голос) і `voiceDialogSettings`. Копія в `/data`,
змонтована поверх оригіналу, набуває чинності після перезапуску ролей квазара.

Хмара також надсилає налаштування під час роботи, і вони мають пріоритет над
файлом: змінений `uniProxyUrl` невдовзі після старту перезаписується в пам'яті.
Якщо вказати в `common.backendUrl` адресу, яка не резолвиться (наприклад,
`nosync.invalid`), синхронізація зупиняється — ціною хмарних функцій, які від неї
залежать.

## user_config.dat

`/data/quasar/data/user_config.dat` — це protobuf із конфігурацією акаунта, яку
хмара надіслала востаннє. Його можна редагувати на місці, якщо кожен змінений
рядок зберігає свою довжину в байтах, щоб не змінювався жоден префікс довжини:
наприклад, URL тієї ж довжини, доповнений фіктивним параметром на кшталт
`?pad=1234567`. Збережіть оригінал і захистіть змінений файл `chattr +i`, інакше
наступна синхронізація його замінить.

Після тривалого перебування без мережі токен у ньому спливає; повторне
підключення колонки в застосунку Яндекса записує свіжий файл.

Ці перевизначення були потрібні для [Quasar Bridge](11-quasar-bridge.md) і в
підсумковій конфігурації не використовуються.
