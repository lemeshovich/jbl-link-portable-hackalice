# Як підмінити файли прошивки

[English](../en/05-overriding-the-firmware.md) · **Українська** · [Русский](../ru/05-overriding-the-firmware.md)

## Bind-монтування

Кореневу систему на запис не перемонтуєш, але свій файл із `/data` можна
змонтувати поверх наявного:

```
mount -o bind /data/path/replacement /system/vendor/quasar/quasar.cfg
```

Що треба знати:

- підмінити можна лише те, що вже існує; створити так новий файл, наприклад
  `/home/root/.asoundrc`, не вийде;
- після перезавантаження монтування зникає, тож його треба повторювати з хука;
- програми, які вже відкрили файл, бачитимуть старий, доки їх не перезапустити.

## quasar.cfg

У `/system/vendor/quasar/quasar.cfg` лежать налаштування демонів, зокрема
`uniProxyUrl` (куди йде голос) і `voiceDialogSettings`. Копія в `/data`,
змонтована поверх оригіналу, почне діяти після перезапуску ролей квазара.

Але хмара під час роботи теж надсилає налаштування, і вони сильніші за файл:
змінений `uniProxyUrl` уже за кілька секунд після старту знову стає штатним. Якщо
вказати в `common.backendUrl` адресу, яка не резолвиться (скажімо,
`nosync.invalid`), синхронізація зупиняється — але разом з нею перестають
працювати й хмарні функції, що від неї залежать.

## user_config.dat

`/data/quasar/data/user_config.dat` — це protobuf з налаштуваннями акаунта, які
хмара надіслала востаннє. Його можна правити просто в файлі, якщо кожен змінений
рядок лишається тієї ж довжини в байтах і не зсуває жоден префікс довжини.
Наприклад, URL можна замінити іншим тієї ж довжини, доповнивши його фіктивним
параметром на зразок `?pad=1234567`. Оригінал збережіть, а змінений файл
закрийте через `chattr +i`, інакше наступна синхронізація його перезапише.

Якщо колонка довго була без мережі, токен у файлі спливає. Лікується це повторним
підключенням колонки в застосунку Яндекса — він запише свіжий файл.

Усе це знадобилося для [Quasar Bridge](11-quasar-bridge.md), а в робочій
конфігурації вже не використовується.
