# ytm-alice на старій прошивці

[English](../en/09-ytm-alice-port.md) · **Українська** · [Русский](../ru/09-ytm-alice-port.md)

[ytm-alice](https://github.com/SPAWNRYS-ban/ytm-alice) — клієнт YouTube Music для
колонок Яндекса. Він слухає Алісу і забирає собі музичні команди. Писали його під
новіші прошивки, і тут розказано, як ми запустили його на quasar 3.21. Як
працює голосове керування, докладно описано в [розділі 10](10-voice-control.md).

## Бінарники

| Файл | Що це |
|---|---|
| `ytm-alice` | сам демон і утиліта командного рядка, Go, зібраний з нашим патчем із `patches/` |
| `ytm-alice-resolver` | допоміжна програма на QuickJS-ng, яка розшифровує адреси потоків; статична |
| `ytm-alice-player` | обгортка на shell, див. [device/ytm/ytm-alice-player](../../device/ytm/ytm-alice-player) |
| `ytm-play` | власне програвач, див. [розділ 08](08-ytm-play.md) |

Усі чотири файли кладемо в `/data/ytm/bin/`, налаштування ALSA — у
`/data/ytm/my.conf`.

ytm-alice запускає `ytm-alice-player` зі свого каталогу й передає йому адресу на
кшталт `http://127.0.0.1:18883/audio/...`. Обгортка задає `ALSA_CONFIG_PATH` і
запускає `ytm-play -D ytmout`. GStreamer із прошивки тут не задіяний узагалі.

Як зібрати: [patches/build-ytm-alice.sh](../../patches/build-ytm-alice.sh)
клонує ytm-alice з коміту `923e9acc2517184c447853e00e96eb600f5cef94`, накладає
[патч](../../patches/ytm-alice-quasar-3.21.patch) і збирає обидві програми
(Go 1.27.3, для resolver — `arm-linux-gnueabihf-gcc` 13.3.0, стискання UPX 4.2.2).
Результат збігається з бінарниками з релізу байт у байт.

## Перший запуск

```
cd /data/ytm/bin
./ytm-alice login tv          # покаже код і адресу, де його ввести
./ytm-alice daemon start
./ytm-alice status
```

Вхід через TV не злітає з часом, як сесія в браузері. Веб-панель — на порту
24721, а для трансляції колонка видна під назвою «Яндекс Станция».

## Власні голосові команди

У веб-панелі є список власних голосових команд: фраза малими літерами і дія до
неї. Наш патч додає дію **Мои лайки** (у `settings.json` вона зветься `liked`).
Тоді, наприклад, фраза `включи музыку` вмикатиме ваші лайки. Без неї просте
«включи музыку» ytm-alice не підхоплює, і Аліса відповідає, що потрібна підписка
Плюс.

## Автозапуск

[device/jbl-autostart/hooks.d/30-ytm.sh](../../device/jbl-autostart/hooks.d/30-ytm.sh)
записує `ytm-alice.service` у `/run/systemd/system` і запускає його, не чекаючи.
Юніт:

- стартує після `linkplay.service` і мережі;
- спершу робить `chmod 600` для файлів у `/data/yam/var/local.ytm-alice/`, бо
  ytm-alice не приймає файл сесії з іншими правами («файл сессии должен иметь
  права 600»), а `droproot_setup` скидає їх при кожному завантаженні;
- запускає демон одразу, без затримок. Затримки ніколи не допомагали
  ([розділ 03](03-persistence-and-autostart.md#тиша-після-завантаження-автозапуск-був-ні-до-чого)).

## Що змінює патч

Патч накладається на коміт `923e9acc` і змінює `main.go`, `ipc.go`, `cast.go`,
`playback_options.go`, `settings.go` та `web/app.js`, а ще додає файл із тестами.
Усе, що стосується старої прошивки, вмикається лише тоді, коли в `maind` немає
`AliceCapability` (або коли задано `YTM_ALICE_SPEECH=server_action`). На новіших
прошивках ytm-alice працює як і раніше.

| Що змінили | Навіщо |
|---|---|
| Текст із кадру зі станом 1 переносимо в наступний кадр зі станом 3, де тексту немає | інакше на 3.21 не розпізнається жодна голосова команда |
| Говоримо через `vins_server_action` зі сценарієм «повтори за мною» | `AliceCapability` на 3.21 немає; так повертаються «Включаю» і відповідь на «что сейчас играет» |
| Відмову Аліси прибираємо за її текстом у стані 3 через `cleanup_directive_controller`, а потім розблоковуємо діалог | хмара на кожну перехоплену команду відповідає «видео не поддерживается» або «нужна подписка» |
| На час перехоплення команди глушимо лише Алісу (`ShadowMaster`) | прибрана відповідь іноді ще кількасот мілісекунд долітає до динаміка |
| «Включаю» надсилаємо лише після того, як відмову прибрано, і повторюємо один раз, якщо Аліса не відреагувала | скасування зачіпає й запит, що вже в дорозі; одразу після скасування `aliced` іноді пропускає один запит |
| Закриваємо мікрофон, який сам відкривається після наших запитів | інакше Аліса слухає ще секунд п'ять, а музика весь цей час приглушена |
| Тримаємо з'єднання з IPC пів секунди після запису | `aliced` губить повідомлення, якщо з'єднання закрити надто рано |
| Повторена фраза вважається новою командою, якщо між ними прозвучало «Аліса» | друге «дальше» протягом 10 секунд ігнорувалося як дубль |
| Гучність читаємо й задаємо через елемент `Master`, а не через `amixer sget/sset Master` | інакше після завантаження колонка замовкає ([розділ 07](07-audio.md#підступне-підсилення-після-завантаження)) |
| На «дальше» і «назад» нічого не кажемо | оригінальний ytm-alice озвучує і перемикання треків |
| Пишемо журнал `/tmp/ytm-voice.log` | у ньому видно стани Аліси й кожну дію; він невеликий і сам себе очищає |
| Додали дію «Мои лайки» для власних голосових команд (`liked`) | щоб фраза на кшталт простого «включи музыку» вмикала лайки, а не відповідь Аліси про підписку |

Тести на розбір кадрів, розпізнавання відмов і затримку «Включаю» лежать у
`legacy_voice_test.go`. Тести самого ytm-alice теж проходять.
