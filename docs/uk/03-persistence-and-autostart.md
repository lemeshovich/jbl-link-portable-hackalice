# Збереження змін і автозапуск

[English](../en/03-persistence-and-autostart.md) · **Українська** · [Русский](../ru/03-persistence-and-autostart.md)

У кореневій файловій системі лише для читання нічого не змінити, а
`droproot_setup` при кожному завантаженні скидає права в `/data`. Тож автозапуск
треба «підвісити» на щось, що прошивка й так запускає і що читає конфігурацію з
`/data`.

## Плагін Fluent Bit (PR #141)

Ідея й код належать lonsdaleite
([PR #141](https://github.com/Marker284/yandex-station-extended/pull/141)):

1. Штатний `fluent-bit` 1.4.6 читає `/data/quasar/fluent-bit/device.cfg`. До
   нього дописується один рядок: `@INCLUDE /data/jbl-autostart/fluent-service.cfg`,
   а файл захищається `chattr +i`, щоб його не перезаписали.
2. Цей include завантажує крихітний вхідний плагін
   [`flb-in_jbl_bootstrap.so`](../../device/jbl-autostart/fluent_bootstrap.c), єдине
   завдання якого — один раз запустити `/data/jbl-autostart/bootstrap.sh` і
   повернути керування.
3. `bootstrap.sh` встановлює `jbl-autostart.service` у `/run/systemd/system` і
   запускає його, не чекаючи.
4. Служба запускає `run.sh`, який по черзі виконує `hooks.d/*.sh`, перевіривши
   власника й права кожного хука.

Усе дерево `/data/jbl-autostart` захищене `chattr -R +i`. Щоб змінити хук:

```
chattr -R -i /data/jbl-autostart
# правка, chmod 700, chown 0:0
chattr -R +i /data/jbl-autostart
```

У PR плагін збирається clang і lld; тут — Zig, і він щоразу дає той самий файл:
[device/jbl-autostart/build-plugin.sh](../../device/jbl-autostart/build-plugin.sh).

## Наші хуки

| Хук | Що робить |
|---|---|
| `05-no-ota.sh` | При кожному завантаженні знову вмикає захист від OTA, див. [04](04-ota-protection.md) |
| `10-ssh.sh` | З PR: запускає Dropbear |
| `30-ytm.sh` | Встановлює `ytm-alice.service` у `/run` і запускає його, не чекаючи |
| `40-llm.sh` | Так само встановлює `llm-alice.service` (`Restart=on-failure`), див. [15](15-llm-alice.md) |
| `90-marker.sh` | З PR: записує ідентифікатор завантаження як доказ того, що хуки відпрацювали |

Файл `/data/jbl-autostart/ytm-off` змушує `30-ytm.sh` пропустити ytm-alice, а
`/data/jbl-autostart/llm-off` робить те саме для llm-alice.

## Хуки мають завершуватися швидко

Хуки виконуються всередині однієї oneshot-служби з обмеженням у 30 секунд. Усе
довготривале має жити у власному юніті. `30-ytm.sh` лише записує юніт і викликає
`systemctl start --no-block`; порядок запуску після `linkplay.service` і мережі
визначає systemd.

Фоновий процес, запущений із хука або з рядка `ExecStartPre`, systemd вбиває,
щойно цей крок завершується. Довготривалі програми запускайте як основний процес
юніта.

## Тиша після завантаження, яка не стосувалась автозапуску

Довго ytm-alice, запущений при завантаженні, лишав колонку без звуку, тоді як той
самий бінарник, запущений пізніше через SSH, працював нормально. Затримки,
очікування аудіостека, «розігрів» мікшера, порядок запуску systemd і оточення
процесу нічого не змінювали. Справжньою причиною був один виклик
`amixer sget Master` у ytm-alice, який лише на щойно завантаженій колонці
скидає підсилення кодека майже до нуля. Усі ручні перевірки робились одразу після
перезапуску `linkplay.service`, який якраз це виправляє. Див.
[07, баг із підсиленням після завантаження](07-audio.md#баг-із-підсиленням-після-завантаження).
