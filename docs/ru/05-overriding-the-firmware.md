# Как подменить файлы прошивки

[English](../en/05-overriding-the-firmware.md) · [Українська](../uk/05-overriding-the-firmware.md) · **Русский**

## Bind-монтирование

Корневую систему на запись не перемонтируешь, но свой файл из `/data` можно
смонтировать поверх существующего:

```
mount -o bind /data/path/replacement /system/vendor/quasar/quasar.cfg
```

Что нужно знать:

- подменить можно только то, что уже существует; создать так новый файл,
  например `/home/root/.asoundrc`, не выйдет;
- после перезагрузки монтирование пропадает, так что его нужно повторять из хука;
- программы, которые уже открыли файл, будут видеть старый, пока их не
  перезапустить.

## quasar.cfg

В `/system/vendor/quasar/quasar.cfg` лежат настройки демонов, в том числе
`uniProxyUrl` (куда уходит голос) и `voiceDialogSettings`. Копия в `/data`,
смонтированная поверх оригинала, начнёт действовать после перезапуска ролей
квазара.

Но облако во время работы тоже присылает настройки, и они сильнее файла:
изменённый `uniProxyUrl` уже через несколько секунд после старта снова становится
штатным. Если указать в `common.backendUrl` адрес, который не резолвится (скажем,
`nosync.invalid`), синхронизация останавливается — но вместе с ней перестают
работать и облачные функции, которые от неё зависят.

## user_config.dat

`/data/quasar/data/user_config.dat` — это protobuf с настройками аккаунта, которые
облако прислало последними. Его можно править прямо в файле, если каждая
изменённая строка остаётся той же длины в байтах и не сдвигает ни один префикс
длины. Например, URL можно заменить другим той же длины, дополнив его фиктивным
параметром вроде `?pad=1234567`. Оригинал сохраните, а изменённый файл закройте
через `chattr +i`, иначе следующая синхронизация его перезапишет.

Если колонка долго была без сети, токен в файле протухает. Лечится это повторным
подключением колонки в приложении Яндекса — оно запишет свежий файл.

Всё это понадобилось для [Quasar Bridge](11-quasar-bridge.md), а в рабочей
конфигурации уже не используется.
