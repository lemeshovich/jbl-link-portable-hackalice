# Переопределение прошивки

[English](../en/05-overriding-the-firmware.md) · [Українська](../uk/05-overriding-the-firmware.md) · **Русский**

## Bind-монтирование поверх корня только для чтения

Корневую файловую систему нельзя перемонтировать на запись, но файл из `/data`
можно смонтировать поверх существующего файла:

```
mount -o bind /data/path/replacement /system/vendor/quasar/quasar.cfg
```

Ограничения:

- только поверх файла или каталога, который уже существует; новый путь вроде
  `/home/root/.asoundrc` так не создать;
- монтирование исчезает после перезагрузки, поэтому его нужно повторять из хука;
- процессы, которые уже открыли файл, видят старый, пока их не перезапустить.

## quasar.cfg

`/system/vendor/quasar/quasar.cfg` содержит конфигурацию демонов, в том числе
`uniProxyUrl` (куда идёт голос) и `voiceDialogSettings`. Копия в `/data`,
смонтированная поверх оригинала, вступает в силу после перезапуска ролей квазара.

Облако также присылает настройки во время работы, и они имеют приоритет над
файлом: изменённый `uniProxyUrl` вскоре после старта перезаписывается в памяти.
Если указать в `common.backendUrl` адрес, который не резолвится (например,
`nosync.invalid`), синхронизация останавливается — ценой облачных функций,
которые от неё зависят.

## user_config.dat

`/data/quasar/data/user_config.dat` — это protobuf с конфигурацией аккаунта,
которую облако прислало последней. Его можно редактировать на месте, если каждая
изменённая строка сохраняет свою длину в байтах, чтобы не менялся ни один
префикс длины: например, URL той же длины, дополненный фиктивным параметром вроде
`?pad=1234567`. Сохраните оригинал и защитите изменённый файл `chattr +i`, иначе
следующая синхронизация его заменит.

После долгого пребывания без сети токен в нём истекает; повторное подключение
колонки в приложении Яндекса записывает свежий файл.

Эти переопределения были нужны для [Quasar Bridge](11-quasar-bridge.md) и в
итоговой конфигурации не используются.
