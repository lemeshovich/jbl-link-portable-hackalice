# Сохранение изменений и автозапуск

[English](../en/03-persistence-and-autostart.md) · [Українська](../uk/03-persistence-and-autostart.md) · **Русский**

В корневой файловой системе только для чтения ничего не изменить, а
`droproot_setup` при каждой загрузке сбрасывает права в `/data`. Поэтому
автозапуск нужно «подвесить» на то, что прошивка и так запускает и что читает
конфигурацию из `/data`.

## Плагин Fluent Bit (PR #141)

Идея и код принадлежат lonsdaleite
([PR #141](https://github.com/Marker284/yandex-station-extended/pull/141)):

1. Штатный `fluent-bit` 1.4.6 читает `/data/quasar/fluent-bit/device.cfg`. К нему
   дописывается одна строка: `@INCLUDE /data/jbl-autostart/fluent-service.cfg`, а
   файл защищается `chattr +i`, чтобы его не перезаписали.
2. Этот include загружает крошечный входной плагин
   [`flb-in_jbl_bootstrap.so`](../../device/jbl-autostart/fluent_bootstrap.c),
   единственная задача которого — один раз запустить
   `/data/jbl-autostart/bootstrap.sh` и вернуть управление.
3. `bootstrap.sh` устанавливает `jbl-autostart.service` в `/run/systemd/system` и
   запускает его, не дожидаясь.
4. Служба запускает `run.sh`, который по очереди выполняет `hooks.d/*.sh`,
   проверив владельца и права каждого хука.

Всё дерево `/data/jbl-autostart` защищено `chattr -R +i`. Чтобы изменить хук:

```
chattr -R -i /data/jbl-autostart
# правка, chmod 700, chown 0:0
chattr -R +i /data/jbl-autostart
```

В PR плагин собирается clang и lld; здесь — Zig, и он каждый раз даёт один и тот
же файл: [device/jbl-autostart/build-plugin.sh](../../device/jbl-autostart/build-plugin.sh).

## Наши хуки

| Хук | Что делает |
|---|---|
| `05-no-ota.sh` | При каждой загрузке снова включает защиту от OTA, см. [04](04-ota-protection.md) |
| `10-ssh.sh` | Из PR: запускает Dropbear |
| `30-ytm.sh` | Устанавливает `ytm-alice.service` в `/run` и запускает его, не дожидаясь |
| `40-llm.sh` | Так же устанавливает `llm-alice.service` (`Restart=on-failure`), см. [15](15-llm-alice.md) |
| `90-marker.sh` | Из PR: записывает идентификатор загрузки как доказательство того, что хуки отработали |

Файл `/data/jbl-autostart/ytm-off` заставляет `30-ytm.sh` пропустить ytm-alice, а
`/data/jbl-autostart/llm-off` делает то же для llm-alice.

## Хуки должны завершаться быстро

Хуки выполняются внутри одной oneshot-службы с ограничением в 30 секунд. Всё
долгоживущее должно жить в собственном юните. `30-ytm.sh` только записывает юнит
и вызывает `systemctl start --no-block`; порядок запуска после `linkplay.service`
и сети определяет systemd.

Фоновый процесс, запущенный из хука или из строки `ExecStartPre`, systemd убивает,
как только этот шаг завершается. Долгоживущие программы запускайте как основной
процесс юнита.

## Тишина после загрузки, не связанная с автозапуском

Долгое время ytm-alice, запущенный при загрузке, оставлял колонку без звука, тогда
как тот же бинарник, запущенный позже через SSH, работал нормально. Задержки,
ожидание аудиостека, «прогрев» микшера, порядок запуска systemd и окружение
процесса ничего не меняли. Настоящей причиной был один вызов `amixer sget Master`
в ytm-alice, который только на только что загруженной колонке сбрасывает
усиление кодека почти до нуля. Все ручные проверки делались сразу после
перезапуска `linkplay.service`, который как раз это исправляет. См.
[07, ошибка с усилением после загрузки](07-audio.md#ошибка-с-усилением-после-загрузки).
