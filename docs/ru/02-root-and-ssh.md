## Root через ADB

Во время загрузки прошивка на несколько секунд открывает USB ADB. Если в этот
момент колонка подключена кабелем USB-C, можно получить оболочку root:

```
adb wait-for-usb-device shell "touch /tmp/lock_activated_adb && ..."
```

Файл `/tmp/lock_activated_adb` не даёт `maind` закрыть USB ADB до следующей
перезагрузки. А файл `/data/network_adb` заставляет `adbd` слушать ещё и TCP-порт
5555 — так мы впервые добрались до колонки по сети. Оба маркера создаёт скрипт
`enable-adb.sh` из PR и защищает их через `chattr +i`.

Помните, что сетевой ADB — это root без всякого пароля для всех в вашей сети. Как
только заработает SSH, его стоит убрать: снять `chattr -i` с `/data/network_adb`
и удалить файл. USB ADB при загрузке никуда не денется — это ваш запасной вход.

## SSH

На порту 2222 работает Dropbear, пускает только по ключу. Лежит он в
`/data/jbl-ssh/`:

- собран статически с musl с помощью Zig, вход по паролю и PAM отключены ещё при
  сборке: [device/ssh/build-dropbear.sh](../../device/ssh/build-dropbear.sh);
- стартует при загрузке через скрипт `ssh-service.sh` из PR, который вызывает хук
  `10-ssh.sh` и создаёт временный юнит systemd в `/run`;
- весь каталог `/data/jbl-ssh` защищён `chattr -R +i`, так что `droproot_setup` не
  сможет ослабить права на ключи.

Заведите для колонки отдельную пару ключей ed25519, а ключ хоста сохраните
где-нибудь вне колонки. Скрипт `install-ssh.sh` из PR делает всё это с
проверками; на нашей прошивке мы прошли те же шаги вручную.

## Как передавать файлы без scp

SFTP в этом Dropbear нет. Из `cmd` в Windows работают два способа. Обычный:

```
type file | ssh -p 2222 root@<колонка> "cat > /data/path/file"
```

И через base64, если файл должен пройти через буфер обмена без повреждений:

```
type file.b64 | ssh -p 2222 root@<колонка> "base64 -d > /data/path/file"
```

Прежде чем запускать бинарник, сверьте `sha256sum` на ПК и на колонке.
