## Root через ADB

Во время загрузки прошивка ненадолго открывает USB ADB. Если при старте колонки
подключён USB-C, несколько секунд доступна root-оболочка:

```
adb wait-for-usb-device shell "touch /tmp/lock_activated_adb && ..."
```

`/tmp/lock_activated_adb` не даёт `maind` снова закрыть USB ADB до следующей
перезагрузки. `/data/network_adb` заставляет `adbd` слушать ещё и TCP 5555 —
именно так был получен первый доступ по сети. Скрипт `enable-adb.sh` из PR
создаёт эти маркеры и защищает их `chattr +i`.

Сетевой ADB — это root-оболочка без аутентификации для всей локальной сети. Когда
заработает SSH, уберите его: снимите `chattr -i` с `/data/network_adb` и удалите
файл. USB ADB при загрузке остаётся запасным входом.

## SSH

Dropbear работает как сервер только со входом по ключу на порту 2222, из
`/data/jbl-ssh/`:

- собран статически с musl с помощью Zig, без аутентификации по паролю и PAM:
  [device/ssh/build-dropbear.sh](../../device/ssh/build-dropbear.sh);
- запускается при загрузке скриптом `ssh-service.sh` из PR через хук `10-ssh.sh`,
  который пишет временный юнит systemd в `/run`;
- всё дерево `/data/jbl-ssh` защищено `chattr -R +i`, поэтому `droproot_setup` не
  может ослабить права на ключи.

Используйте отдельную пару ключей ed25519 и храните резервную копию ключа хоста
вне устройства. Скрипт `install-ssh.sh` из PR выполняет эти шаги с проверками; на
этой прошивке те же шаги сделаны вручную.

## Передача файлов без scp

Dropbear здесь без подсистемы SFTP. Два способа, которые работают из `cmd` в
Windows:

```
type file | ssh -p 2222 root@<колонка> "cat > /data/path/file"
```

и, для всего, что должно пережить копирование через буфер обмена, base64:

```
type file.b64 | ssh -p 2222 root@<колонка> "base64 -d > /data/path/file"
```

Всегда сравнивайте `sha256sum` с обеих сторон, прежде чем использовать бинарник.
