# ytm-alice на старой прошивке

[English](../en/09-ytm-alice-port.md) · [Українська](../uk/09-ytm-alice-port.md) · **Русский**

[ytm-alice](https://github.com/SPAWNRYS-ban/ytm-alice) — клиент YouTube Music для
колонок Яндекса. Он слушает Алису и забирает себе музыкальные команды. Писали его
под новые прошивки, а здесь рассказано, как мы запустили его на quasar 3.21. Как
устроено голосовое управление, подробно описано в [разделе 10](10-voice-control.md).

## Бинарники

| Файл | Что это |
|---|---|
| `ytm-alice` | сам демон и утилита командной строки, Go, собранный с нашим патчем из `patches/` |
| `ytm-alice-resolver` | вспомогательная программа на QuickJS-ng, которая расшифровывает адреса потоков; статическая |
| `ytm-alice-player` | обёртка на shell, см. [device/ytm/ytm-alice-player](../../device/ytm/ytm-alice-player) |
| `ytm-play` | собственно проигрыватель, см. [раздел 08](08-ytm-play.md) |

Все четыре файла кладём в `/data/ytm/bin/`, настройки ALSA — в
`/data/ytm/my.conf`.

ytm-alice запускает `ytm-alice-player` из своего каталога и передаёт ему адрес
вроде `http://127.0.0.1:18883/audio/...`. Обёртка задаёт `ALSA_CONFIG_PATH` и
запускает `ytm-play -D ytmout`. GStreamer из прошивки здесь не участвует вовсе.

Как собрать: [patches/build-ytm-alice.sh](../../patches/build-ytm-alice.sh)
клонирует ytm-alice с коммита `923e9acc2517184c447853e00e96eb600f5cef94`,
накладывает [патч](../../patches/ytm-alice-quasar-3.21.patch) и собирает обе
программы (Go 1.27.3, для resolver — `arm-linux-gnueabihf-gcc` 13.3.0, сжатие
UPX 4.2.2). Результат совпадает с бинарниками из релиза байт в байт.

## Первый запуск

```
cd /data/ytm/bin
./ytm-alice login tv          # покажет код и адрес, где его ввести
./ytm-alice daemon start
./ytm-alice status
```

Вход через TV не слетает со временем, как сессия в браузере. Веб-панель — на
порту 24721, а для трансляции колонка видна под именем «Яндекс Станция».

## Свои голосовые команды

В веб-панели есть список своих голосовых команд: фраза строчными буквами и
действие к ней. Наш патч добавляет действие **Мои лайки** (в `settings.json` оно
называется `liked`). Тогда, например, фраза `включи музыку` будет включать ваши
лайки. Без него простое «включи музыку» ytm-alice не подхватывает, и Алиса
отвечает, что нужна подписка Плюс.

## Автозапуск

[device/jbl-autostart/hooks.d/30-ytm.sh](../../device/jbl-autostart/hooks.d/30-ytm.sh)
записывает `ytm-alice.service` в `/run/systemd/system` и запускает его, не
дожидаясь. Юнит:

- стартует после `linkplay.service` и сети;
- сначала делает `chmod 600` для файлов в `/data/yam/var/local.ytm-alice/`,
  потому что ytm-alice не принимает файл сессии с другими правами («файл сессии
  должен иметь права 600»), а `droproot_setup` сбрасывает их при каждой загрузке;
- запускает демон сразу, без задержек. Задержки никогда не помогали
  ([раздел 03](03-persistence-and-autostart.md#тишина-после-загрузки-автозапуск-был-ни-при-чем)).

## Что меняет патч

Патч накладывается на коммит `923e9acc` и меняет `main.go`, `ipc.go`, `cast.go`,
`playback_options.go`, `settings.go` и `web/app.js`, а ещё добавляет файл с
тестами. Всё, что касается старой прошивки, включается только тогда, когда в
`maind` нет `AliceCapability` (или когда задано `YTM_ALICE_SPEECH=server_action`).
На новых прошивках ytm-alice работает как раньше.

| Что изменили | Зачем |
|---|---|
| Текст из кадра с состоянием 1 переносим в следующий кадр с состоянием 3, где текста нет | иначе на 3.21 не распознаётся ни одна голосовая команда |
| Говорим через `vins_server_action` со сценарием «повтори за мной» | `AliceCapability` на 3.21 нет; так возвращаются «Включаю» и ответ на «что сейчас играет» |
| Отказ Алисы убираем по его тексту в состоянии 3 через `cleanup_directive_controller`, а потом разблокируем диалог | облако на каждую перехваченную команду отвечает «видео не поддерживается» или «нужна подписка» |
| На время перехвата команды глушим только Алису (`ShadowMaster`) | убранный ответ иногда ещё несколько сотен миллисекунд долетает до динамика |
| «Включаю» отправляем только после того, как отказ убран, и повторяем один раз, если Алиса не отреагировала | отмена задевает и запрос, который уже в пути; сразу после отмены `aliced` иногда пропускает один запрос |
| Закрываем микрофон, который сам открывается после наших запросов | иначе Алиса слушает ещё секунд пять, а музыка всё это время приглушена |
| Держим соединение с IPC полсекунды после записи | `aliced` теряет сообщения, если соединение закрыть слишком рано |
| Повторённая фраза считается новой командой, если между ними прозвучало «Алиса» | второе «дальше» в течение 10 секунд игнорировалось как дубль |
| Громкость читаем и задаём через элемент `Master`, а не через `amixer sget/sset Master` | иначе после загрузки колонка замолкает ([раздел 07](07-audio.md#коварное-усиление-после-загрузки)) |
| На «дальше» и «назад» ничего не говорим | оригинальный ytm-alice озвучивает и переключение треков |
| Пишем журнал `/tmp/ytm-voice.log` | в нём видны состояния Алисы и каждое действие; он небольшой и сам себя чистит |
| Добавили действие «Мои лайки» для своих голосовых команд (`liked`) | чтобы фраза вроде простого «включи музыку» включала лайки, а не ответ Алисы про подписку |

Тесты на разбор кадров, распознавание отказов и задержку «Включаю» лежат в
`legacy_voice_test.go`. Тесты самого ytm-alice тоже проходят.
