# Порт ytm-alice

[English](../en/09-ytm-alice-port.md) · [Українська](../uk/09-ytm-alice-port.md) · **Русский**

[ytm-alice](https://github.com/SPAWNRYS-ban/ytm-alice) — клиент YouTube Music для
колонок Яндекса, который слушает Алису и берёт на себя музыкальные команды. Он
написан под более новые прошивки. Эта страница описывает, как его запустили на
quasar 3.21; [10](10-voice-control.md) подробно описывает голосовое управление.

## Бинарники

| Файл | Что |
|---|---|
| `ytm-alice` | демон и CLI, Go, собранный с патчем из `patches/` |
| `ytm-alice-resolver` | вспомогательная программа на QuickJS-ng, расшифровывающая адреса потоков, статическая |
| `ytm-alice-player` | обёртка на shell, см. [device/ytm/ytm-alice-player](../../device/ytm/ytm-alice-player) |
| `ytm-play` | собственно плеер, см. [08](08-ytm-play.md) |

Все четыре идут в `/data/ytm/bin/`. Конфиг ALSA — в `/data/ytm/my.conf`.

ytm-alice запускает `ytm-alice-player` из своего каталога с адресом
`http://127.0.0.1:18883/audio/...`; обёртка задаёт `ALSA_CONFIG_PATH` и запускает
`ytm-play -D ytmout`. GStreamer прошивки не используется вовсе.

Сборка: [patches/build-ytm-alice.sh](../../patches/build-ytm-alice.sh) клонирует
ytm-alice на коммите `923e9acc2517184c447853e00e96eb600f5cef94`, накладывает
[патч](../../patches/ytm-alice-quasar-3.21.patch) и собирает обе программы
(Go 1.27.3, `arm-linux-gnueabihf-gcc` 13.3.0 для resolver, UPX 4.2.2). Результат
побайтово совпадает с бинарниками из релиза.

## Первый запуск

```
cd /data/ytm/bin
./ytm-alice login tv          # печатает код и адрес, где его ввести
./ytm-alice daemon start
./ytm-alice status
```

Вход через TV не истекает, как сеанс браузера. Веб-панель — на порту 24721, а
колонка появляется как цель трансляции с названием «Яндекс Станция».

## Свои голосовые команды

В веб-панели есть список своих голосовых команд: фраза строчными буквами и
действие. Патч добавляет действие **Мои лайки** (`liked` в `settings.json`),
чтобы, например, `включи музыку` включало лайки. Без него просто «включи музыку»
не относится к ytm-alice, и Алиса отвечает, что нужна подписка Плюс.

## Автозапуск

[device/jbl-autostart/hooks.d/30-ytm.sh](../../device/jbl-autostart/hooks.d/30-ytm.sh)
записывает `ytm-alice.service` в `/run/systemd/system` и запускает его, не
дожидаясь. Юнит:

- запускается после `linkplay.service` и сети;
- сначала выполняет `chmod 600` для файлов в `/data/yam/var/local.ytm-alice/`, так
  как ytm-alice отказывается от файла сессии с правами, отличными от 600, а
  `droproot_setup` сбрасывает их при каждой загрузке («файл сессии должен иметь
  права 600»);
- запускает демон без какой-либо задержки. Задержки никогда не были решением
  ([03](03-persistence-and-autostart.md#тишина-после-загрузки-не-связанная-с-автозапуском)).

## Что меняет патч

Относительно коммита `923e9acc` в upstream, в `main.go`, `ipc.go`, `cast.go`,
`playback_options.go`, `settings.go` и `web/app.js`, плюс файл тестов.
Всё, что касается конкретной прошивки, включается только тогда, когда `maind` не
содержит `AliceCapability` (или когда задано `YTM_ALICE_SPEECH=server_action`),
поэтому более новые прошивки сохраняют исходное поведение.

| Изменение | Зачем |
|---|---|
| Переносить распознанный текст из кадра состояния 1 в кадр состояния 3 без текста | иначе на 3.21 ни одна голосовая команда не распознаётся |
| Говорить через `vins_server_action` + `repeat_after_me` | речи через `AliceCapability` на 3.21 нет; возвращает «Включаю» и «что сейчас играет» |
| Отбрасывать отказ Алисы по его тексту в состоянии 3 через `cleanup_directive_controller`, затем освобождать диалог | на каждую перехваченную команду облако отвечает «видео не поддерживается» или «нужна подписка» |
| Глушить только Алису (`ShadowMaster`), пока команда перехватывается | отброшенный ответ иногда ещё несколько сотен мс доходит до динамика |
| Отправлять объявление только после того, как отказ отброшен, и повторить один раз, если Алиса его не подхватила | отмена отменяет и запрос в пути; сразу после отмены `aliced` иногда игнорирует один запрос |
| Закрывать микрофон, который сам открывается после наших запросов | иначе Алиса слушает около 5 с, и музыка остаётся приглушённой |
| Держать IPC-соединения открытыми 0,5 с после записи | `aliced` теряет сообщения от соединений, которые закрываются слишком рано |
| Повторённая фраза — новая команда, если между ними было слово активации | «дальше» дважды за 10 с игнорировалось как дублирующийся кадр |
| Читать и задавать громкость через элемент регулятора `Master` вместо `amixer sget/sset Master` | доступ через простой микшер глушит колонку после загрузки ([07](07-audio.md#ошибка-с-усилением-после-загрузки)) |
| Без объявления на «дальше» / «назад» | upstream объявляет и при смене трека |
| `/tmp/ytm-voice.log` | журнал состояний Алисы и каждого действия, небольшой и с ротацией |
| Действие «Мои лайки» для своих голосовых команд (`liked`) | позволяет фиксированной фразе, например просто «включи музыку», включать лайки вместо «нужна подписка» от Алисы |

Тесты для разбора кадров, распознавания отказов и «ворот» объявления — в
`legacy_voice_test.go`; набор тестов upstream проходит.
