# Голосовое управление на старой прошивке

[English](../en/10-voice-control.md) · [Українська](../uk/10-voice-control.md) · **Русский**

Что происходит между «Алиса, включи на ютубе Daft Punk» и музыкой на quasar 3.21,
и зачем каждый шаг. Всё здесь выяснено из голосового журнала
(`/tmp/ytm-voice.log`) и `yiod.log`, а не угадано.

## Проблема

Алиса отправляет каждую команду в облако. ytm-alice видит распознанный текст и сам
включает музыку, но облако тоже ответило, и Алиса вот-вот скажет
«Воспроизведение видео не поддерживается на этом устройстве» или «Для этого нужна
подписка Плюс…». На более новых прошивках ytm-alice отменяет это через IPC
`AliceCapability`, которого на 3.21 нет.

## Что не сработало

- Отменять сразу, как команда распознана: ответ приходит позже, так что отменять
  ещё нечего.
- Отменять в цикле несколько секунд: это закрывает и микрофон Алисы, поэтому
  следующая команда обрывается.
- Заменять ответ пустым запросом «повтори за мной»: ему нужен обмен с облаком на
  0,3–2 с, за которые успевают прозвучать первые слова.
- Сообщения прошивки, похожие на отмену (`restart_vins_dialog`, `sound_cancel`,
  кнопка действия): на 3.21 никакого эффекта.

## Что работает

### 1. Распознать команду

Текст приходит в кадре состояния 1; итоговое состояние 3 — отдельным кадром без
текста. Текст переносится (окно 10 с). Повторённая фраза считается новой
командой, если между ними было событие слова активации.

### 2. Заглушить только Алису

В этот момент `ShadowMaster` (softvol Алисы) сохраняется и ставится в 0. Музыка
на `Master` и играет дальше. Сохранённое значение пишется в
`/tmp/ytm-shadow-saved`; если демон упадёт, пока Алиса заглушена, следующий
запуск его восстановит.

### 3. Отбросить ответ до того, как он произнесён

Ответ появляется в кадре состояния 3 со своим текстом ещё до того, как Алиса
начнёт говорить:

```
state 3 -> 3 speech="Воспроизведение видео не поддерживается на этом устройстве."
refusal in state 3 ...: cleanup_directive_controller
state 3 -> 0
```

Ответ считается отказом, если в нём есть «подписк», «видео», «не
поддерживается» или «недоступ», и только в течение 12 с после команды, которую
взял ytm-alice, — чтобы Алису не глушили, когда её спрашивают о другом.

`cleanup_directive_controller` — собственная отмена диалога прошивкой. Иногда
ответ уже дошёл до звукового тракта, и Алиса ещё до двух секунд «говорит» в
заглушённый канал; заглушение держится, пока она в состоянии 2 с отказом, но в
сумме не дольше 4 с.

### 4. Освободить диалог

Отброшенный ответ оставляет диалог в ожидании воспроизведения, которого никогда
не будет: светодиоды крутятся («думает»), а слово активации игнорируется.
Освобождает его новый запрос. Для «включи» это само объявление; для «пауза»,
«дальше» и остальных — пустой «повтори за мной», на который Алиса отвечает
тишиной.

### 5. Вернуть голос и объявить

`ShadowMaster` восстанавливается примерно через 400 мс после того, как отказ
отброшен (или через 2,5 с после команды, если отказа не было). Только после этого
отправляется «Включаю», потому что отмена отменяет и запрос в пути. Если Алиса не
отреагирует на него за 1,5 с (обычно реагирует примерно за 50 мс), он будет
отправлен ещё раз.

### 6. Закрыть микрофон

После любого нашего запроса прошивка открывает микрофон примерно на пять секунд,
что к тому же держит музыку приглушённой. Когда Алиса переходит в состояние 1 в
течение 10 с после нашего запроса **без** события слова активации перед этим,
демон через секунду отправляет `cleanup_directive_controller` и повторяет, пока
она ещё слушает. Сессия, которую пользователь начинает словом «Алиса», всегда
имеет сначала событие слова активации, и её никогда не трогают.

## Типичный журнал

```
wake word
state 0 -> 1
state 1 -> 3
ShadowMaster 610,610 -> 0 (Alice muted)
intercepted "Включи на YouTube Daft Punk" -> play
state 3 -> 3 speech="Воспроизведение видео не поддерживается на этом устройстве."
refusal in state 3 ...: cleanup_directive_controller
state 3 -> 0
ShadowMaster restored to 610,610
announce queued "Включаю" (attempt 0)
speech sent after 4ms "Включаю" err=<nil>
state 0 -> 3
state 3 -> 2 speech="Окей, повторяю за вами: «Включаю»."
state 2 -> 1
auto-listen opened after our request
auto-listen still open: cleanup_directive_controller
state 1 -> 0
```

## Если Алиса всё же зависла

- **Бесконечно думает** (светодиоды крутятся, игнорирует «Алиса»): `alicesay ""`
  освобождает диалог.
- **Бесконечно слушает**: `alicesay ""`, затем `qcancel -f 170 -E`; если не
  помогает, перезапустите голосовую роль:
  `kill $(ps | grep "[m]aind --yiod" | awk '{print $1}')`. Лаунчер поднимет её
  за несколько секунд.
