## Как устроен ALSA на колонке

Самое важное из `/etc/asound.conf` на этой прошивке:

```
default ──► shadow_softvol (control "ShadowMaster") ──► ... ──► dmixer ──► hw:0,0
softvol ──► softvol (control "Master") ────────────────────────► dmixer
hmpp    ──► Harman DSP plugin (type hmpp) ──► ch2route ─────────► dmixer
```

- **Алиса** говорит через `default`, поэтому её громкостью управляет
  `ShadowMaster` (numid 120).
- **Кнопки громкости** двигают одновременно `Master` (numid 128) и
  `ShadowMaster`, от 0 до 999.
- **Bluetooth** идёт через `hmpp` — обработку звука Harman. Именно она даёт
  колонке настроенный бас; всё, что её обходит, звучит заметно площе.
- `dmixer` — это `dmix` с общей памятью на ключах 1024 и 1025.

## Наш выход ytmout

Для ytm-play мы сделали собственное устройство `ytmout`: softvol на регуляторе
`Master`, который отдаёт звук в `plug:hmpp`. Так что им управляют кнопки, и
звучит он через ту же обработку Harman, что и Bluetooth.

Домашний каталог `/home/root` лежит на корневой системе, а она только для
чтения, так что `~/.asoundrc` не подходит. Вместо этого проигрыватель получает
переменную `ALSA_CONFIG_PATH`, которая указывает на
[device/ytm/my.conf](../../device/ytm/my.conf). В этом файле нужно подключить
**оба** конфига — основной ALSA и системный — и только потом описывать `ytmout`:

```
</usr/share/alsa/alsa.conf>
</etc/asound.conf>
pcm.ytmout { type softvol  slave.pcm "plug:hmpp"  control { name "Master" card 0 } ... }
```

Без первой строки ALSA даже не знает, что такое `plug`.

Есть и приятный бонус: Алиса сидит на `ShadowMaster`, а музыка — на `Master`, так
что ytm-alice может на мгновение заглушить только Алису, а музыка будет играть
дальше. Об этом — в [разделе 10](10-voice-control.md).

## Зависшие подключения к dmix

Если проигрыватель, который играет через `dmixer`, убить жёстко, его подключение
к общей памяти может остаться висеть. Наберётся несколько таких — и замолчит
Bluetooth. В BusyBox нет `ipcrm`, поэтому мы написали
[tools/ipcclean.c](../../tools/ipcclean.c). Лечится так:

```
/data/ytm/bin/ipcclean dmix
systemctl restart linkplay.service      # прозвучит сигнал JBL
```

ytm-play освобождает своё место в обработчике `atexit` и закрывает сокет в
обработчике сигналов, так что с ним такое случаться уже не должно.

## Что прошивка не умеет декодировать

YouTube Music отдаёт AAC в контейнере MP4, обычном или фрагментированном. А на
этой прошивке:

- в GStreamer нет ни декодера AAC, ни разбора MP4; MP3 играет через libmad;
- в `libquasar_gstreamer.so` нужные элементы есть, но наружу они не
  экспортируются;
- `/system/workdir/lib/libfaad_drm.so` содержит API faad2, но собран для Digital
  Radio Mondiale и на обычный AAC отвечает ошибками 29 и 30.

Так что пришлось написать собственный проигрыватель с собственным faad2 —
[раздел 08](08-ytm-play.md).

## Коварное усиление после загрузки

`HW Gain1 Volume` (numid 7) — это аппаратное усиление кодека. В норме оно
`524288`.

На только что загруженной колонке обычное чтение регулятора

```
amixer -c0 sget Master
```

сбрасывает его до `64`. Колонка практически замолкает, Алиса тоже, и так
продолжается, пока не перезапустить `linkplay.service`. После такого перезапуска
та же команда уже ничего не ломает — поэтому проблема так долго и пряталась:
каждая ручная проверка шла сразу после перезапуска, которым мы и спасали звук.

Вернуть `HW Gain1 Volume` через `amixer cset` тоже не выйдет — он тут же снова
становится `64`. Правильное значение выставляет только старт Linkplay.

А вот обращение напрямую к **элементу** регулятора ничего не ломает:

```
amixer -c0 cget numid=128        # или name=Master
amixer -c0 cset numid=128 500,500
```

ytm-alice использовал `sget`/`sset Master`, чтобы показывать и менять громкость во
время трансляции. Наш патч заменил их на обращение к элементу.

## Как такое искать

Сравните состояние микшера до и после:

```
amixer -c 0 contents > mix-bad.txt
# возвращаем звук, а потом
amixer -c 0 contents > mix-good.txt
diff mix-bad.txt mix-good.txt
```

Из 645 строк отличались пять, и среди них — то самое усиление.
