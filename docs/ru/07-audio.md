## Схема ALSA

Важные части `/etc/asound.conf` на этой прошивке:

```
default ──► shadow_softvol (control "ShadowMaster") ──► ... ──► dmixer ──► hw:0,0
softvol ──► softvol (control "Master") ────────────────────────► dmixer
hmpp    ──► Harman DSP plugin (type hmpp) ──► ch2route ─────────► dmixer
```

- **Алиса** говорит через `default`, поэтому её громкость — `ShadowMaster` (numid 120).
- **Кнопки громкости** двигают `Master` (numid 128) и `ShadowMaster` вместе,
  диапазон от 0 до 999.
- **Bluetooth** идёт через `hmpp`, DSP Harman. Именно он даёт колонке настроенный
  бас; всё, что его обходит, звучит заметно площе.
- `dmixer` — это `dmix` с ключами общей памяти 1024 и 1025.

## Наше устройство вывода

ytm-play использует собственное устройство `ytmout`: softvol на регуляторе
`Master`, подающий звук в `plug:hmpp`. Поэтому им управляют кнопки, и он получает
тот же DSP, что и Bluetooth.

Домашний каталог `/home/root` лежит на корне только для чтения, поэтому
`~/.asoundrc` не вариант. Вместо этого плеер получает `ALSA_CONFIG_PATH`,
указывающий на [device/ytm/my.conf](../../device/ytm/my.conf), который должен
подключать **оба** — основной конфиг ALSA и системный — до определения `ytmout`:

```
</usr/share/alsa/alsa.conf>
</etc/asound.conf>
pcm.ytmout { type softvol  slave.pcm "plug:hmpp"  control { name "Master" card 0 } ... }
```

Без первого подключения ALSA вообще не знает тип `plug`.

То, что Алиса на `ShadowMaster`, а музыка на `Master`, позволяет ytm-alice на
мгновение заглушить только Алису, пока музыка играет дальше; см.
[10](10-voice-control.md).

## Зависшие подключения dmix

Если плеер, использующий `dmixer`, жёстко убить, его подключение к сегментам общей
памяти может остаться. Несколько таких — и Bluetooth замолкает. В BusyBox нет
`ipcrm`, поэтому есть [tools/ipcclean.c](../../tools/ipcclean.c). Восстановление:

```
/data/ytm/bin/ipcclean dmix
systemctl restart linkplay.service      # звучит сигнал JBL
```

ytm-play освобождает свой слот в обработчике `atexit` и закрывает сокет в
обработчике сигнала, так что с ним такого быть уже не должно.

## Что прошивка не умеет декодировать

YouTube Music отдаёт AAC в MP4 (обычном или фрагментированном). На этой прошивке:

- в GStreamer нет ни декодера AAC, ни демультиплексора MP4; MP3 работает через
  libmad.
- `libquasar_gstreamer.so` содержит такие элементы, но не экспортирует ни одного.
- `/system/workdir/lib/libfaad_drm.so` экспортирует API faad2, но собран для
  Digital Radio Mondiale и отвергает обычный AAC с ошибками 29 и 30.

Отсюда наш собственный плеер с собственным faad2: [08](08-ytm-play.md).

## Ошибка с усилением после загрузки

`HW Gain1 Volume` (numid 7) — аппаратное усиление кодека, в норме `524288`.

На только что загруженной колонке чтение простого элемента микшера командой

```
amixer -c0 sget Master
```

устанавливает его в `64`: колонка фактически замолкает, и Алиса тоже, пока не
перезапустить `linkplay.service`. После такого перезапуска та же команда
безвредна, поэтому ошибка так долго пряталась: каждая ручная проверка делалась
сразу после перезапуска, нужного для восстановления звука.

`HW Gain1 Volume` не вернуть и через `amixer cset`: он сразу снова читается как
`64`. Устанавливает его только старт Linkplay.

Прямое чтение или запись **элемента** регулятора этого не вызывает:

```
amixer -c0 cget numid=128        # или name=Master
amixer -c0 cset numid=128 500,500
```

ytm-alice использовал `sget`/`sset Master`, чтобы сообщать и задавать громкость
для сеанса трансляции. Патч заменяет их прямым доступом к элементу.

## Как искать такое: сравнить микшер

```
amixer -c 0 contents > mix-bad.txt
# восстановить звук, затем
amixer -c 0 contents > mix-good.txt
diff mix-bad.txt mix-good.txt
```

Из 645 строк отличались пять, и одна из них — то самое усиление.
